JTDX-VU — JTDX for the VUCG community

Active

JTDX-VU is JTDX 2.2.159 built for the VUCG community and kept up to date: native apps for macOS (Apple Silicon and Intel), Windows x64 and Raspberry Pi / Linux (arm64 .deb), with the features VU DXers asked for added on top. It installs next to a stock JTDX as its own app, with its own settings and data, and on first launch copies an existing JTDX setup across, so callsign, audio, rig and logs carry over.

What you get that stock JTDX doesn't have:

  • Your whole log counts. New DXCC / band / mode status comes from your Club Log log, optionally confirmed QSOs only, not just what JTDX logged.
  • AutoSeq goes for what you need. A new DXCC first, then new on the band, then new in the mode, both when answering CQs and when several stations call you.
  • Queue a station. Right-click a decode and AutoSeq calls it the next time it is heard.
  • Auto CQ. One button keeps a CQ run going hands-off, with a time limit, in the FT modes and JTTY alike.
  • Needed-DXCC alerts to the desktop and Telegram, and a one-tick filter that shows only stations you still need.
  • JTTY and FT2. WSJT-X 3.2’s RTTY-style keyboard mode with its own screen and 24 macros, and FT2, the double-speed FT4 created by Martino Merola IU8LMC with Salvatore Raccampo 9H1SR (ARI Caserta).
  • One-click band and mode buttons, as in MSHV.
  • Made for SDRs over TCI. Reconnects by itself, warns when audio stops, a TX slider that follows the SDR program’s drive, an RX level slider, and Fake It split that stays on frequency.
  • Simpler Notifications settings with a live preview, and text-only highlighting if you prefer a plain background.

FlexRadio through a firewall or VPN, Discover and US states (v0.7.4). A FlexRadio sends its audio to the computer over UDP, which a firewall or VPN drops until something goes out the other way; JTDX-VU now sends the radio a small registration packet first, so audio and waterfall come through — confirmed over a VPN to VU2OY’s radio and by KK4CDK on Windows. If no audio arrives twice in a row it stops retrying and says why (usually the firewall), and the red ERR box reconnects. Settings › Radio has a FlexRadio: address box with a Discover button for radios on the same LAN. Show US State (Settings › General) shows U.S.A. stations as U.S.A.:FL, from the decoded grid first and the FCC licence database otherwise (asked for by Miguel KK4CDK). On QO-100, Club Log alerts and JTTY status now look up 13cm, not 3cm.

A check for new releases, %LOG and a steadier Auto CQ button (v0.7.3). About ten seconds after start, at most once a day, JTDX-VU asks GitHub for its latest release — one anonymous request, no token, nothing else sent — and, if there is a newer one, shows its notes with Download (opens the release page), Skip This Version and Remind Me Later. It never downloads or installs anything, the automatic dialog never takes the keyboard from the main window, and Settings › General › Check for updates automatically turns it off; Help › Check for Updates... runs it by hand. A JTTY macro containing %LOG logs the QSO as it is sent, without the Log QSO dialog, once per QSO. The Auto CQ button keeps its width while it counts down and now counts through the first half of each minute too.

FT4 on 70cm and 23cm, an 8m button and an Auto CQ countdown (v0.7.2). FT4 has its own spots on 70cm and 23cm (432.170 and 1296.170 MHz, as Frank PH2M uses them), and there is an 8m button (FT8 on 40.680 MHz, Region 1) for stations with an 8m permit. The new rows are added once to an existing frequency list on first start, so no reset is needed. While Auto CQ is on, its button now counts down the time left before it stops calling: the JTTY time limit, or in FT8 / FT4 / FT2 the Tx watchdog, which runs down while you transmit.

Credits corrected (v0.7.1). The About box now credits the two modes JTDX-VU added: JTTY (K1JT, K9AN, G4KLA and the WSJT-X team) and FT2 (created by Martino Merola IU8LMC with Salvatore Raccampo 9H1SR, ARI Caserta). No other changes from v0.7.0.

FlexRadio without SmartSDR, QO-100, profiles and the rig mode at a glance (v0.7.0). A new FlexRadio VITA-49 rig type talks straight to a FLEX-6000/8000: receive and transmit audio travel over the radio's own DAX streams, so no SmartSDR, DAX driver or TCI bridge is needed, and the TX slider becomes the radio's RF power. A FlexRadio panel shows the radio's meters, antennas and mode and sets power, the antenna tuner and per-band antennas. A QO-100 band button works the satellite and logs the QSO as LoTW expects, also through SDR-Control with a transverter. A Profile menu keeps one settings set per rig. The rig's mode now shows beside the frequency, green when it's right and yellow when the radio is in the wrong mode. FT2 gains MSHV's demapper and AP7 a-priori decoding and now decodes as deep as MSHV on the same audio. Also 70cm and 23cm band buttons, and two crash fixes (TCI reconnect, rare false JTTY decodes).

AutoSeq goes for what you need, a station queue and new Notifications settings (v0.6.0). AutoSeq now takes a new DXCC first, then a DXCC new on the band, then one new in the mode — both when answering CQs and when several stations call you — and it calls only stations decoded in the latest period. Right-click a decode to queue a station: AutoSeq calls it the next time it's heard, before anyone else. The Notifications settings are redesigned, one row per kind of “new” with its colours and beep, a live preview and an option to colour the text instead of the background, and a single New only tick above the decodes follows them. The Pwr slider becomes TX, which over TCI follows the SDR program's own drive, and a new RX slider sets the receive level. Auto CQ and 1 QSO now exclude each other, AnsB4 and 1 QSO stay on across band changes, and each wanted filter can be hidden. Fixed: with Fake It split over TCI the dial could creep several kHz up the band in one transmission.

Auto CQ in one place (v0.5.3). The Auto CQ button now sits directly under Monitor in every mode, FT8/FT4/FT2 and JTTY alike, so it is always where your hand expects it. Status-bar messages are no longer covered by the watchdog box.

Auto CQ only for your own CQ, and TCI reconnect (v0.5.2). Auto CQ now keeps going only after QSOs that came from your own CQ: when you answer someone, Tx halts after that QSO, and while it is on AutoSeq answers only stations calling you (or a station you queued). It is off in Hound mode, and changing band switches it off. TCI reconnects on its own: if the SDR program is closed or restarted, JTDX-VU retries every 5 seconds from the status bar instead of showing the Rig Control Error box, and carries on once the SDR program is back. With TCI audio on it also warns when the SDR program stops sending audio. AetherSDR 26.9.5 users: if TCI audio stops after JTDX-VU has been closed for a while, restart AetherSDR; the fix (AetherSDR#6116) is merged for AetherSDR’s next release.

Auto CQ time limit and window fixes (v0.5.1). Auto CQ now stops after a time limit, 5 minutes by default (1–60 in Settings › JTTY): in JTTY it stops calling once the limit is reached, and in FT8/FT4/FT2 the same limit is the Tx watchdog while Auto CQ is on. The main window now resizes properly — it stops at the size the controls need instead of letting them overlap, and in JTTY extra height goes to the received text — and the two decode panes split about half each in every mode.

JTTY screen (v0.5.0). JTTY now has a screen of its own: the controls that only matter in FT8/FT4/FT2 (Report, Hound, AutoSeq, the wanted filters, Enable Tx, Hint, Decode and the rest) are hidden in JTTY and come back in the other modes. All the buttons sit in one column, and the space holds S / R / Name fields that are logged (RST no longer a fixed 599) and usable in macros as %RST and %NAME, and a calls heard list of the stations sending, coloured from the log or Club Log (new DXCC, new on the band, new in JTTY, new call, worked) — click one to work it. There are 24 macros in three banks (F1–F8, Shift+, Option+) shown as labelled buttons, with a macro-set picker on the panel, type-ahead that queues the next message while one is on the air, and a red blink on a macro key that can't be sent yet because the DX call or name is missing.

JTTY operating (v0.4.0). Auto CQ sends your CQ macro, listens for a gap (10 s by default) and calls again; press it again to stop, which also halts a CQ on the air, and it stops by itself when you pick a caller or (optionally) when a decode contains your call. A click, double-click or selection on a callsign in either JTTY pane puts it in DX Call, N1MM-style, ignoring punctuation around it. A new Settings › JTTY page holds the Auto CQ options, station details for new macro variables (%OP name, %QTH, %TX radio, %ANT antenna) and named macro sets — “Contest (WSJT-X)” sends 599 %N, “Ragchew / DX” just 599. JTTY QSOs now log as 599 / 599 and as ADIF MFSK / JTTY. v0.4.0 also fixes a crash when quitting while TCI is still connecting, and the Settings dialog on small (1366×768) screens. The one Auto CQ button serves the FT modes and JTTY, and Monitor is the start/stop for receiving.

JTTY and FT2 (v0.3.0). JTTY is WSJT-X 3.2’s period-free, RTTY-style keyboard mode, ported from 3.2.0-rc1: it decodes continuously, transmits the moment you press Send, and has the rc1 controls page — F1–F8 with editable macros, a free-text entry, Call next and Serial Number. JTTY is by Joe Taylor K1JT, Steve Franke K9AN, Rob G4KLA and the WSJT-X team. FT2 is FT4’s protocol at twice the speed (3.75 s periods), created by Martino Merola IU8LMC (ARI Caserta) with Salvatore Raccampo 9H1SR as lead C++ developer; it first went on air in Decodium on 2026-02-16 (ft2.it) and MSHV by LZ2HV added it in 2.76.5 on 2026-03-24. JTDX-VU decodes and transmits it with a scaled copy of JTDX’s own FT4 chain, now with MSHV’s more accurate demodulator, and works MSHV stations on the air; its weak-signal reach is being brought up to MSHV’s.

From the first releases (v0.1–v0.2).

Club Log DXCC status. JTDX's new DXCC / band / mode colouring normally reflects only the QSOs JTDX itself logged. JTDX-VU can take the whole log from Club Log instead, so every contact made with any program counts. It can also count only QSOs confirmed by QSL, LoTW or eQSL, which keeps worked-but-unconfirmed entities showing as needed. The log is refreshed at start-up, and QSOs made since the last refresh still count, so a station just worked doesn't light up again.

Needed-DXCC alerts. When a decoded station is an ATNO, a new band or a new mode, JTDX-VU raises a desktop notification and/or sends a Telegram message, with a per-station cooldown.

Auto CQ in the FT modes keeps working stations hands-off: after each logged QSO it goes straight back to CQ or the next caller, dropping a station that doesn't answer after the AutoSeq counters, and stops after the Auto CQ time limit if nobody answers.

One-click band and mode buttons above the decode panes, after the MSHV switcher: the current band and mode light up green, and a band button tunes to the mode's standard frequency. Also a shorter title bar, a Settings dialog that no longer squashes on macOS, and no focus-stealing when a new DXCC decodes.

Based on JTDX by Igor Chernikov UA3DJY, Arvo Järve ES1JA and the HF community, itself derived from WSJT-X by Joe Taylor K1JT and the WSJT development team. GPL v3, with source on GitHub.

Tested so far. macOS (Apple Silicon) is in daily use here: Club Log download, Telegram and desktop alerts, band/mode buttons, Auto CQ, the new-only filter, JTTY with Auto CQ and click-to-pick, and Fake It split over TCI. QO-100 through SDR-Control is in use here, and the FlexRadio rig connects, receives and changes band on a FLEX-6600; its transmit side is so far tested on a simulated radio only (v0.7.0). FT2 decodes as deep as MSHV on identical test audio but hasn’t yet been worked against an MSHV station on air. The Auto CQ countdown (v0.7.2) is checked in JTTY and on an idle FT8 watchdog; its run-down during an FT8 CQ run is still to be seen on air. The release check (v0.7.3) is confirmed in the installed app. On Windows, Club Log, Telegram and desktop alerts are confirmed, and KK4CDK has made and logged QSOs with the FlexRadio VITA-49 rig type. The Raspberry Pi package passes a simulated install and starts, but isn't yet used on air.

Installing. Step-by-step instructions for each OS are in the README and the release notes. In short — macOS: unzip, move to Applications, allow the first open (System Settings › Privacy & Security › Open Anyway on Sequoia; the app isn't notarized), and make the one-time shared-memory setting. Windows: unzip and run bin\jtdx.exe (SmartScreen › More info › Run anyway). Pi: sudo apt install ./jtdx-vu-0.7.4-linux-arm64.deb.
